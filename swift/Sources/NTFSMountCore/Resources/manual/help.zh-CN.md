# NTFSMount 使用手册

## 1. 这个工具做什么，不做什么

macOS 自带能**读** NTFS，不能写。NTFSMount 补上的是写这一半：它调用 `ntfs-3g` 这个成熟的开源 NTFS 驱动，配合 `macFUSE` 提供的用户态文件系统框架，把一个 NTFS 卷重新挂载成可读可写，让它在访达里跟普通磁盘一样能存文件。

同样重要的是它**不做**什么。下面这些事它一件都不做：

- 不格式化、不分区、不转换文件系统格式；
- 不修改分区表，不动引导记录；
- 不碰 Windows 的访问控制列表（ACL）与加密体系；
- 不做数据恢复。「重置」功能里的 `ntfsfix` 只清除「脏分区」标记，它不修复文件内容；
- 不在后台常驻任何第三方进程、不联网、不上传任何信息。

> [!WARN]
> 任何写入 NTFS 的操作都存在风险，这一点跟用哪种工具无关。第一次对某块盘动写操作之前，请把里面的重要文件另行备份一份。本工具按「现状」提供，不对数据丢失承担责任。

> [!IMPORTANT]
> 数据的完整性有很大一部分取决于硬件本身。劣质闪存颗粒的 U 盘在持续写入时会掉速、报错甚至掉盘，表现得却像软件出了问题。要做大量读写，请用读写性能有保障的移动硬盘或固态 U 盘。

## 2. 运行环境与依赖关系

| 项目 | 要求 |
| --- | --- |
| 操作系统 | macOS 14.0 或更高 |
| 处理器 | Apple Silicon 与 Intel 均有对应安装包 |
| 必需依赖 | macFUSE、ntfs-3g |
| 磁盘占用 | 约 30 MB（应用本体 4 MB 上下） |

依赖不是并列的两项，而是一条链：

```
NTFSMount        ->  ntfs-3g        ->  macFUSE        ->  macOS kernel
  (UI)                 (driver)           (framework)        (system)
```

`ntfs-3g` 懂 NTFS 的磁盘结构，但它自己没法直接和 macOS 内核对话 —— 它需要一个「用户态文件系统」的中间层把内核的文件请求转给自己，这一层就是 `macFUSE`。缺哪一环，挂载都成不了。

> [!NOTE]
> 本应用是一个纯原生实现：界面、设备检测与挂载流程全部基于系统框架，没有第三方运行时，也没有常驻的辅助进程。设备插拔由系统原生的 IOKit 与 DiskArbitration 通知感知，不做轮询；空闲时 CPU 占用接近 0。

## 3. 准备系统依赖

### 3.1 先让应用告诉你缺什么

打开应用，进入「系统依赖」页，点右上角「检查依赖」。这一页会列出四项的实际状态：

1. macOS 版本是否满足最低要求；
2. Xcode Command Line Tools 是否安装（安装 ntfs-3g 时可能用到）；
3. macFUSE 是否就位；
4. ntfs-3g 是否就位。

每一条都能展开，展开后是这一项该装什么、用什么命令装。命令旁边有复制按钮。缺失的项会标红，装好的项标绿。

> [!TIP]
> 装完依赖不用重启应用，也不用再点一次「检查依赖」。这一页每三秒自动重查一次（纯文件系统检查，不启动进程），你在终端里 `brew install` 或 `port install` 装完，切回窗口就能看到状态自己变绿。

### 3.2 MacPorts（Intel Mac 首选）

```bash
sudo port install macfuse
```

```bash
sudo port install ntfs-3g
```

MacPorts 把所有东西装在 `/opt/local` 下。本应用会把 `/opt/local/bin` 一并纳入搜索范围，装完即被识别，不需要你配 `PATH`，也不需要告诉应用去哪儿找。

### 3.3 Homebrew（Apple Silicon 首选）

```bash
brew install --cask macfuse
```

```bash
brew tap gromgit/homebrew-fuse && brew install ntfs-3g-mac
```

`ntfs-3g-mac` 这个 tap 提供的是适配 Apple Silicon 的构建版本。

### 3.4 从发布页自行安装

也可以不用包管理器，从项目发布页下载安装：

- macFUSE：https://macfuse.github.io
- ntfs-3g：https://github.com/tuxera/ntfs-3g

自行安装时容易遇到的是路径问题：装到非标准位置，应用就找不到。遇到这种情况，请确认可执行文件落在 `/usr/local/bin`、`/opt/local/bin` 或 `/opt/homebrew/bin` 之一。

### 3.5 安装顺序与验证

先 `macFUSE`，后 `ntfs-3g`。反过来的话后者会因为找不到框架而安装失败。

装完在终端验证一次：

```bash
ntfs-3g --version
```

能打印出版本号就说明路径没问题 —— 应用识别的就是这个可执行文件。

> [!IMPORTANT]
> 安装 macFUSE 之后，macOS 会拦住它的系统扩展并弹出提示。必须去「系统设置 → 隐私与安全性」，在下方找到来自 macFUSE 的条目并点「允许」，然后按提示重启电脑。这一步不做，挂载会失败，报的是权限问题 —— 跟 NTFS 本身没有关系。

### 3.6 关于版本

应用会对 `ntfs-3g` 的版本做一次检查：低于建议版本时在依赖页给出升级提示；对已知存在回归的版本（会导致无法新建文件与目录）给出明确警告。它不会替你升级，只告诉你该升级了。

## 4. 走通第一次挂载

1. 插上 NTFS 格式的移动磁盘。macOS 会先把它以**只读**方式挂上，访达里能看到卷，但存不进东西。
2. 打开 NTFSMount，切到「NTFS 设备」页，点「刷新」或等它自动刷新。
3. 在列表里找到目标设备，看「设备挂载点」那一列是不是挂着只读状态。
4. 点这一行右侧的「读写」按钮。
5. 系统弹出授权对话框，输入你的 Mac 登录密码（若已开启「保存管理员密码」，此步不会弹出）。
6. 挂载成功后，这一行状态变成「可读写」，访达里的卷也能正常写入。

现在可以往卷里写文件了。用完想恢复成系统默认的只读状态，点这一行的「还原为只读」；想彻底断开这块盘，点「推出」。

> [!NOTE]
> 第 5 步弹出的窗口是 macOS 自己的授权框，不是本应用画出来的界面。它支持 Touch ID 与 Apple Watch，密码由系统的 `securityd` 直接校验，本应用拿不到你输入的密码。这是默认路径，也是更安全的路径。

## 5. 主界面导览

主窗口是标准的 macOS 分栏布局：左侧导航，右侧内容，底部一条状态栏。

### 5.1 侧边栏的四个页面

- **系统依赖** —— 检查 macFUSE 与 ntfs-3g，看安装指引。
- **NTFS 设备** —— 设备列表与全部操作都在这里。
- **操作日志** —— 每次挂载、卸载、失败的时间与原因。默认关闭，需在设置里开启。
- **指南手册** —— 你正在看的这一页。左侧目录可搜索，代码块可一键复制。

设置**不**在侧边栏里。它按 macOS 的惯例放在应用菜单的「设置…」（⌘,）里；侧边栏再放一个只会造成两个入口指向同一处。

### 5.2 底部状态栏

状态栏用一个圆点加一句话概括当前情况：

| 颜色 | 含义 |
| --- | --- |
| 灰色 | 正在检查依赖 |
| 绿色 | 就绪。后面会写有几个设备可读写、几个只读 |
| 橙色 | 有问题但不致命 |
| 红色 | 依赖缺失，挂载功能不可用 |

### 5.3 设备页工具栏

从左到右：**刷新**、**全读写**、**全只读**、**全卸载**、**全推出**。搜索框也在工具栏里，可以按卷名或设备名筛选。

批量按钮作用于**当前选中的行**；一行都没选时作用于全部设备。

## 6. 设备页：状态怎么读

### 6.1 三种状态

| 显示 | 含义 | 能否写入 |
| --- | --- | --- |
| 可读写 | 已经由 ntfs-3g 接管，正在读写挂载 | 可以 |
| 只读 | 系统内置 NTFS 驱动的只读挂载 | 不可以 |
| 已卸载 | 你已经把它卸载，但设备还插着 | 不可以 |

「已卸载」这个状态是特意保留的：拔设备之前你会先卸载，卸载后它不该从列表里消失 —— 否则你会以为设备掉了。要让它彻底消失，用「推出」。

### 6.2 容量条

每一行的设备名下面都有一条容量条，显示「可用 / 总容量」和占用百分比。设备未挂载时容量依然显示 —— 容量是读取文件系统头部信息得到的，不需要挂载就能拿到。

容量条的颜色分三档：

- 蓝色（默认）—— 占用低于 75%；
- 橙色 —— 占用 75% 到 90%，该留意了；
- 红色 —— 超过 90%，该清理了。

分三档而不是做连续渐变，是因为这条进度条在界面上只有几毫米宽，渐变在那个尺寸下根本分辨不出来。

### 6.3 挂载点

「设备挂载点」这一列显示的是 `/Volumes/<name>` 这类路径。设备未挂载时显示「未挂载」。挂载读写之后，路径就是访达里能访问到的那一个。

## 7. 设备页：六个操作各自做什么

六个操作全在每行的右侧。它们的区别不只是「挂」和「不挂」，选错了轻则白忙一场，重则中断正在进行的传输。

| 操作 | 它实际做的事 | 什么时候用 |
| --- | --- | --- |
| 读写 | 先卸载当前的只读挂载，再用 ntfs-3g 以读写方式挂上 | 要往盘里写东西 |
| 重新读写 | 先卸载，再以读写方式重新挂载一次 | 读写状态下出问题，想重来一次 |
| 还原为只读 | 卸载后交回系统内置驱动，以只读方式挂载 | 写完了，想回到最保守的状态 |
| 卸载 | 卸载，但设备仍留在列表里 | 拔盘之前 |
| 推出 | 从系统里彻底断开这块设备 | 确定不再使用，要拔走 |
| 重置 | 卸载 → `ntfsfix` 清脏标志 → 只读重挂 | 报「Resource busy」或用不了的时候 |

### 7.1 读写

挂载前会先检查 macFUSE 与 ntfs-3g 是否就位。缺任何一个都会直接告诉你缺什么、去哪儿装，不会弹出一个看不懂的错误，也不会让你对着不动的图标猜。

### 7.2 还原为只读

这个操作会先卸载当前挂载，再让系统内置驱动重新以只读方式挂上。**它不会丢数据**，前提是此刻没有程序正在往这块盘里写。有正在进行的复制或下载时，先等它结束。

### 7.3 卸载与推出的区别

卸载只是把文件系统摘下来，设备仍然连着，可以随时再挂上。推出是真的把设备从系统里断开，拔线之前做这一下最稳妥。推出之后设备会从列表中消失，要重新插一次才会回来。

### 7.4 重置

有些故障靠单纯重挂解决不了，比如上一次异常退出留下的脏标志、或者某个程序占着盘不放。重置会做三件事：强制卸载、调用 `ntfsfix` 清除 NTFS 的脏标志、以只读方式挂回来。清完标志之后通常就能正常读写了。

> [!NOTE]
> `ntfsfix` 清的是「分区不干净」这个标记，它不检查也不修复文件内容。如果你的盘是在 Windows 非正常关机后出现的问题，清完标志通常就恢复了；但如果是文件系统结构本身损坏，需要的是 Windows 自带的磁盘检查功能，不是这个按钮。

### 7.5 批量操作

工具栏的批量按钮作用于当前选中的行；没有选中任何行时作用于全部。批量挂载会依次为每台设备发起操作 —— 如果没有保存管理员密码，你会看到连续的授权对话框，这是预期行为。

## 8. 挂载参数

挂载时的参数由应用统一决定，一个都不需要你手工指定。列在这里是为了出问题时你能看懂：

| 参数 | 作用 |
| --- | --- |
| `-olocal` | 让系统把这个卷当作本地卷而不是网络卷。影响它在访达里出现在「位置」还是「网络」 |
| `-oallow_other` | 允许挂载者以外的进程访问这个卷。不开的话只有 root 能读，桌面环境下等于用不了 |
| `-oremove_hiberfile` | 卷被 Windows 休眠占用时删除休眠文件，换取可写挂载 |
| `-onoatime` | 不更新文件的「最后访问时间」。每次读都写一次索引记录是纯粹的写放大 |
| `-ovolname` | 让卷在访达里显示正确的名字 |

> [!IMPORTANT]
> `-oremove_hiberfile` 的语义要说清楚：Windows 的「快速启动」会把关机前的系统状态写进休眠文件，此时 NTFS 卷处于「正在被使用」的状态。加了这个参数，应用会删掉那个休眠文件，从而拿到写权限 —— **代价是 Windows 那边未保存的会话状态就此丢失**。如果你在 Windows 里还有没保存的东西，先插回 Windows 正常关机。

## 9. I/O 块大小

这是唯一一个面向性能的可调项，位置在「设置 → 挂载参数」。

macFUSE 向你访问的每个卷暴露一块「假想存储设备」，`iosize` 决定内核向文件系统发起 I/O 请求时的块大小。macFUSE 自身的默认值是 64 KiB，而它官方文档写得很直白：链路快的时候（比如本地磁盘）取大块能显著降低访问开销。一块本地 USB 或雷雳硬盘显然属于「快链路」。

| 档位 | 适用场景 |
| --- | --- |
| macFUSE 默认（64 KiB） | 机械硬盘；以海量小文件为主、几乎不做连续大文件读写 |
| 1 MiB（推荐） | 默认档位。固态盘与移动硬盘的通用场景 |
| 4 MiB | 以超大文件为主：视频素材、磁盘映像、整盘备份 |

改完设置对**下一次挂载**生效，已经挂着的设备需要重新读写一次。

> [!NOTE]
> 该参数有格式约束：必须是 2 的幂，最大 32 MiB。应用给出的三个档位都在安全范围内，因此你不需要记这些限制 —— 但如果你在别处手工挂载，请留意。

## 10. 权限与管理员密码

挂载读写需要管理员权限。应用提供两种取得权限的方式。

### 10.1 默认方式：系统授权对话框

每次需要提权时弹出 macOS 自己的对话框，密码由系统校验，本应用全程接触不到。支持 Touch ID 与 Apple Watch。这是默认方式，安全性更高。

### 10.2 可选方式：保存管理员密码

在「设置 → 系统集成」里打开「保存管理员密码」，输入一次密码并点「验证并保存」。此后挂载不再弹框。

密码存在 macOS 钥匙串里，条目类型是通用密码，归属本应用的包标识。应用自身的任何日志、任何文件里都不会出现这个密码。

> [!WARN]
> 请如实理解这个取舍：保存密码比每次手动输入**安全性更低**。区别在于密码由本应用代为提交，而不是由系统直接向用户索取。如果这台 Mac 有他人共用，或者你对机器上软件的来源没有把握，请不要打开它。

### 10.3 开关有三种状态，不要混淆

| 开关 | 钥匙串里有密码 | 实际行为 |
| --- | --- | --- |
| 关 | 无所谓 | 每次都弹系统授权对话框 |
| 开 | 没有 | **仍然弹框**。开关只表达了意图，此时还没有可用的密码 |
| 开 | 有 | 不弹框，用保存的密码提权 |

第二种状态会单独标一行橙色提示，就是为了避免你对着一个打开的开关纳闷「为什么还是弹框」。

### 10.4 密码失效时会怎样

如果你后来改了 Mac 的登录密码，钥匙串里存的那份就失效了。此时应用会：删掉失效的密码、在日志与设置页说明这件事、并退回系统授权对话框，让你这一次的操作仍然能完成。不会出现「反复失败却永远好不了」的情况。

### 10.5 怎么彻底删掉

把「保存管理员密码」开关关掉即可 —— 关闭这个动作本身就包含删除钥匙串里的条目。也可以在「钥匙串访问」应用里搜索本应用的包标识手工删除。

## 11. 开机行为：四个开关怎么配合

这四个开关都跟「启动」和「自动」有关，很容易混。它们各自只管一件事：

| 设置项 | 管的事 |
| --- | --- |
| 系统自启 | 开机时**是否启动**这个应用 |
| 静默自启 | 开机启动时**是否打开主窗口**。打开后只驻留菜单栏 |
| 开机自动挂载读写 | 启动那一刻，把**已经插在机器上**的 NTFS 设备挂载为读写 |
| 自动读写 | 应用运行期间，**之后新插入**的设备自动挂载为读写 |

几个典型的组合：

- 只想开机就有一块盘可以直接写：打开「系统自启」+「开机自动挂载读写」。
- 开机即在后台待命、不想看见窗口跳出来：再加上「静默自启」。
- 不想开机自动挂，但希望以后插什么盘都自动可写：只开「自动读写」。
- 连授权框都不想要：再打开「保存管理员密码」，此时开机挂载是无人值守完成的。

> [!TIP]
> 「静默自启」打开后，应用在菜单栏只留一个图标，程序坞里不出现。左键点它即可管理设备；右键菜单里有「主界面」；从主界面关掉窗口不会退出应用，它会回到菜单栏继续待命。

## 12. 菜单栏图标与快捷面板

关闭主窗口不会退出应用 —— 这是菜单栏常驻应用的基本行为。窗口关掉之后，应用从菜单栏图标继续工作。

### 12.1 左键点击图标

弹出一块快捷面板，里面直接列出所有 NTFS 设备。每台设备显示：

- 状态图标与卷名；
- 卷的挂载状态；
- **容量条**：「可用 / 总容量」与占用百分比；
- 右侧的操作按钮。

不打开主窗口就能完成挂载、卸载、还原、推出。面板里显示的状态与主界面是同一份数据，不存在两处不同步的问题。

图标本身也会变：有设备处于读写状态时换成另一个图标，一眼就能看出「现在有盘是可写的」。

### 12.2 操作失败时面板会说什么

失败原因直接显示在那一行下面，红色，带警告图标，写的是**完整的一句话**，不截断。这条设计是必需的而不是锦上添花 —— 快捷面板没有日志页，如果失败信息只写进日志，你在这个小面板里点「读写」会看到「点了没反应」：没有弹框、没有提示、图标也不变。

最常见的那一条是依赖没装：此时会明确写出缺的是 macFUSE 还是 ntfs-3g，以及去「系统依赖」页安装。

### 12.3 右键点击图标

菜单包含：主界面、刷新设备列表、全读写、全卸载、设置、退出。

## 13. 访达集成

应用内置一个访达扩展。它给 `/Volumes` 下的卷加上两样东西。

### 13.1 卷标徽标

在访达里看卷的图标，右下角会有一个小徽标，写着当前状态：**读写**、**只读**、**未挂载**。不用回到应用就能知道这块盘现在能不能写。

### 13.2 右键菜单与工具栏

访达工具栏上会出现本应用的按钮，点开是「打开 NTFSMount」。在 `/Volumes` 下的卷上点右键，会多出一组菜单项：

- 挂载为读写
- 卸载
- 恢复只读
- 弹出
- 重置卷（ntfsfix）
- 在 NTFSMount 中显示

在访达里就能直接完成操作，不必切回主窗口。

> [!NOTE]
> 访达扩展由系统按需加载，首次使用可能需要一点时间才出现在菜单里。如果一直不出现，去「系统设置 → 通用 → 登录项与扩展 → 访达扩展」确认它处于开启状态。

## 14. 操作日志

「操作日志」页记录每一次操作的时间、内容与结果。它默认关闭，需要到「设置 → 通用」里打开「启用操作日志」才会开始记录。

面板里可以清空日志，也可以把它导出成文本文件。日志只写在本机的应用支持目录下，不会上传到任何地方。

遇到问题要反馈时，请把导出的日志一并附上 —— 里面的失败原因通常是判断问题的关键，光看现象描述往往猜不到。

## 15. 按症状排错

| 你看到的 | 真正的原因 | 怎么办 |
| --- | --- | --- |
| 列表里没有我的盘 | 分区不是 NTFS；或设备尚未被系统识别 | 先确认这块盘确实是 NTFS 格式；拔掉重插一次；点「刷新」 |
| 提示缺少 macFUSE / ntfs-3g | 依赖没装 | 到「系统依赖」页按指引安装 |
| 提示 Windows is hibernated | Windows 开了快速启动，卷被休眠文件占用 | 插回 Windows，执行 `shutdown /s /t 0` 完全关机，再插回来 |
| 提示 Resource busy | 有程序正在使用这块盘 | 关掉占用它的程序；或用「重置」按钮 |
| 提示权限不足 | macFUSE 的系统扩展没被批准 | 「系统设置 → 隐私与安全性」里允许 macFUSE，然后重启 |
| 提示密码错误 | 保存的密码已失效 | 重新在设置里输入并保存一次 |
| 挂载后写不进去 | 实际还是只读挂载 | 看这一行状态是否为「可读写」；不是就再点一次「读写」 |
| 传输中途掉盘 | 硬件或供电问题 | 换线、换口；避免使用无独立供电的 USB Hub |
| 访达扩展不出现 | 扩展未启用 | 「系统设置 → 通用 → 登录项与扩展」里确认已开启 |

## 16. 卸载与彻底清理

1. 先把所有 NTFS 设备「还原为只读」或「推出」，不要让它们停在读写状态。
2. 退出应用。菜单栏图标右键 → 退出，或按 ⌘Q。
3. 到「设置 → 系统集成」里关闭「系统自启」—— 否则重启后它会再回来。
4. 把应用从「应用程序」文件夹拖到废纸篓。
5. 如果开启过「保存管理员密码」，到「钥匙串访问」里搜索本应用的包标识并删除对应条目。
6. 若不再需要挂载 NTFS，可以一并卸载这两个依赖。Homebrew 是 `brew uninstall ntfs-3g-mac` 与 `brew uninstall --cask macfuse`，MacPorts 是 `sudo port uninstall ntfs-3g macfuse`。

应用的配置文件位于 `~/Library/Application Support/NTFSMount/`，删掉该目录即可清除全部设置。
