# NTFSMount 使用手冊

## 1. 這個工具做什麼，不做什麼

macOS 內建能**讀** NTFS，不能寫。NTFSMount 補上的是寫的這一半：它呼叫 `ntfs-3g` 這個成熟的開源 NTFS 驅動程式，搭配 `macFUSE` 提供的使用者態檔案系統框架，把一個 NTFS 卷重新掛載成可讀可寫，讓它在 Finder 裡跟一般磁碟一樣能存放檔案。

同樣重要的是它**不做**什麼。下面這些事它一件都不做：

- 不格式化、不分割、不轉換檔案系統格式；
- 不修改分割表，不動開機記錄；
- 不碰 Windows 的存取控制清單（ACL）與加密體系；
- 不做資料救援。「重置」功能裡的 `ntfsfix` 只清除「髒分割區」標記，它不修復檔案內容；
- 不在背景常駐任何第三方處理程序、不連線網路、不上傳任何資訊。

> [!WARN]
> 任何寫入 NTFS 的操作都存在風險，這一點跟用哪種工具無關。第一次對某塊磁碟進行寫入操作之前，請把裡面的重要檔案另行備份一份。本工具依「現狀」提供，不對資料遺失承擔責任。

> [!IMPORTANT]
> 資料的完整性有很大一部分取決於硬體本身。劣質快閃記憶體顆粒的隨身碟在持續寫入時會掉速、報錯甚至掉盤，表現得卻像軟體出了問題。要做大量讀寫，請用讀寫效能有保障的外接硬碟或固態隨身碟。

## 2. 執行環境與相依關係

| 項目 | 要求 |
| --- | --- |
| 作業系統 | macOS 14.0 或更高 |
| 處理器 | Apple Silicon 與 Intel 均有對應安裝套件 |
| 必要相依項目 | macFUSE、ntfs-3g |
| 磁碟佔用 | 約 30 MB（應用程式本體 4 MB 上下） |

相依不是並列的兩項，而是一條鏈：

```
NTFSMount        ->  ntfs-3g        ->  macFUSE        ->  macOS kernel
  (UI)                 (driver)           (framework)        (system)
```

`ntfs-3g` 懂 NTFS 的磁碟結構，但它自己沒辦法直接和 macOS 核心對話 —— 它需要一個「使用者態檔案系統」的中間層，把核心的檔案請求轉給自己，這一層就是 `macFUSE`。缺哪一環，掛載都成不了。

> [!NOTE]
> 本應用程式是純原生實作：介面、裝置偵測與掛載流程全部基於系統框架，沒有第三方執行環境，也沒有常駐的輔助處理程序。裝置插拔由系統原生的 IOKit 與 DiskArbitration 通知感知，不做輪詢；閒置時 CPU 佔用接近 0。

## 3. 準備系統相依項目

### 3.1 先讓應用程式告訴你缺什麼

開啟應用程式，進入「系統相依」頁，點右上角「檢查相依」。這一頁會列出四項的實際狀態：

1. macOS 版本是否符合最低需求；
2. Xcode Command Line Tools 是否安裝（安裝 ntfs-3g 時可能用到）；
3. macFUSE 是否就位；
4. ntfs-3g 是否就位。

每一條都能展開，展開後是這一項該裝什麼、用什麼指令安裝。指令旁邊有複製按鈕。缺少的項目會標紅，裝好的項目標綠。

> [!TIP]
> 裝完相依項目不用重新開啟應用程式，也不用再點一次「檢查相依」。這一頁每三秒自動重查一次（單純檔案系統檢查，不啟動處理程序），你在終端機裡 `brew install` 或 `port install` 裝完，切回視窗就能看到狀態自己變綠。

### 3.2 MacPorts（Intel Mac 首選）

```bash
sudo port install macfuse
```

```bash
sudo port install ntfs-3g
```

MacPorts 把所有東西裝在 `/opt/local` 下。本應用程式會把 `/opt/local/bin` 一併納入搜尋範圍，裝完即被辨識，不需要你設定 `PATH`，也不需要告訴應用程式去哪裡找。

### 3.3 Homebrew（Apple Silicon 首選）

```bash
brew install --cask macfuse
```

```bash
brew tap gromgit/homebrew-fuse && brew install ntfs-3g-mac
```

`ntfs-3g-mac` 這個 tap 提供的是適配 Apple Silicon 的建置版本。

### 3.4 從發布頁自行安裝

也可以不用套件管理器，從專案發布頁下載安裝：

- macFUSE：https://macfuse.github.io
- ntfs-3g：https://github.com/tuxera/ntfs-3g

自行安裝時容易遇到的是路徑問題：裝到非標準位置，應用程式就找不到。遇到這種情況，請確認可執行檔落在 `/usr/local/bin`、`/opt/local/bin` 或 `/opt/homebrew/bin` 之一。

### 3.5 安裝順序與驗證

先 `macFUSE`，後 `ntfs-3g`。反過來的話後者會因為找不到框架而安裝失敗。

裝完在終端機驗證一次：

```bash
ntfs-3g --version
```

能印出版本號就說明路徑沒問題 —— 應用程式辨識的就是這個可執行檔。

> [!IMPORTANT]
> 安裝 macFUSE 之後，macOS 會攔下它的系統延伸功能並彈出提示。必須去「系統設定 → 隱私權與安全性」，在下方找到來自 macFUSE 的項目並點「允許」，然後依提示重新啟動電腦。這一步不做，掛載會失敗，回報的是權限問題 —— 跟 NTFS 本身沒有關係。

### 3.6 關於版本

應用程式會對 `ntfs-3g` 的版本做一次檢查：低於建議版本時在相依頁給出升級提示；對已知存在回歸的版本（會導致無法新增檔案與目錄）給出明確警告。它不會替你升級，只告訴你該升級了。

## 4. 完成第一次掛載

1. 插上 NTFS 格式的外接磁碟。macOS 會先把它以**唯讀**方式掛上，Finder 裡能看到卷，但存不進東西。
2. 開啟 NTFSMount，切到「NTFS 裝置」頁，點「重新整理」或等它自動重新整理。
3. 在列表裡找到目標裝置，看「裝置掛載點」那一欄是不是掛著唯讀狀態。
4. 點這一列右側的「讀寫」按鈕。
5. 系統彈出授權對話框，輸入你的 Mac 登入密碼（若已開啟「儲存管理者密碼」，此步驟不會彈出）。
6. 掛載成功後，這一列狀態變成「可讀寫」，Finder 裡的卷也能正常寫入。

現在可以往卷裡寫檔案了。用完想還原成系統預設的唯讀狀態，點這一列的「還原為唯讀」；想徹底斷開這塊磁碟，點「推出」。

> [!NOTE]
> 第 5 步彈出的視窗是 macOS 自己的授權框，不是本應用程式繪製出來的介面。它支援 Touch ID 與 Apple Watch，密碼由系統的 `securityd` 直接驗證，本應用程式拿不到你輸入的密碼。這是預設路徑，也是更安全的路徑。

## 5. 主介面導覽

主視窗是標準的 macOS 分欄佈局：左側導覽，右側內容，底部一條狀態列。

### 5.1 側邊欄的四個頁面

- **系統相依** —— 檢查 macFUSE 與 ntfs-3g，看安裝指引。
- **NTFS 裝置** —— 裝置列表與全部操作都在這裡。
- **操作日誌** —— 每次掛載、卸載、失敗的時間與原因。預設關閉，需在設定裡開啟。
- **指南手冊** —— 你正在看的這一頁。左側目錄可搜尋，程式碼區塊可一鍵複製。

設定**不**在側邊欄裡。它依 macOS 的慣例放在應用程式選單的「設定…」（⌘,）裡；側邊欄再放一個只會造成兩個入口指向同一處。

### 5.2 底部狀態列

狀態列用一個圓點加一句話概括目前情況：

| 顏色 | 含義 |
| --- | --- |
| 灰色 | 正在檢查相依 |
| 綠色 | 就緒。後面會寫有幾個裝置可讀寫、幾個唯讀 |
| 橙色 | 有問題但不致命 |
| 紅色 | 相依項目缺少，掛載功能無法使用 |

### 5.3 裝置頁工具列

從左到右：**重新整理**、**全部讀寫**、**全部唯讀**、**全部卸載**、**全部推出**。搜尋框也在工具列裡，可以依卷名或裝置名稱篩選。

批次按鈕作用於**目前選取的列**；一列都沒選時作用於全部裝置。

## 6. 裝置頁：狀態怎麼讀

### 6.1 三種狀態

| 顯示 | 含義 | 能否寫入 |
| --- | --- | --- |
| 可讀寫 | 已經由 ntfs-3g 接管，正在讀寫掛載 | 可以 |
| 唯讀 | 系統內建 NTFS 驅動程式的唯讀掛載 | 不可以 |
| 已卸載 | 你已經把它卸載，但裝置還插著 | 不可以 |

「已卸載」這個狀態是特意保留的：拔裝置之前你會先卸載，卸載後它不該從列表裡消失 —— 否則你會以為裝置掉了。要讓它徹底消失，用「推出」。

### 6.2 容量條

每一列的裝置名稱下面都有一條容量條，顯示「可用 / 總容量」和佔用百分比。裝置未掛載時容量依然顯示 —— 容量是讀取檔案系統表頭資訊得到的，不需要掛載就能取得。

容量條的顏色分三級：

- 藍色（預設）—— 佔用低於 75%；
- 橙色 —— 佔用 75% 到 90%，該留意了；
- 紅色 —— 超過 90%，該清理了。

分成三級而不是做連續漸層，是因為這條進度條在介面上只有幾公釐寬，漸層在那個尺寸下根本分辨不出來。

### 6.3 掛載點

「裝置掛載點」這一欄顯示的是 `/Volumes/<name>` 這類路徑。裝置未掛載時顯示「未掛載」。掛載讀寫之後，路徑就是 Finder 裡能存取到的那一個。

## 7. 裝置頁：六個操作各自做什麼

六個操作全在每一列的右側。它們的區別不只是「掛」和「不掛」，選錯了輕則白忙一場，重則中斷正在進行的傳輸。

| 操作 | 它實際做的事 | 什麼時候用 |
| --- | --- | --- |
| 讀寫 | 先卸載目前的唯讀掛載，再用 ntfs-3g 以讀寫方式掛上 | 要往磁碟裡寫東西 |
| 重新讀寫 | 先卸載，再以讀寫方式重新掛載一次 | 讀寫狀態下出問題，想重來一次 |
| 還原為唯讀 | 卸載後交回系統內建驅動程式，以唯讀方式掛載 | 寫完了，想回到最保守的狀態 |
| 卸載 | 卸載，但裝置仍留在列表裡 | 拔磁碟之前 |
| 推出 | 從系統裡徹底斷開這塊裝置 | 確定不再使用，要拔走 |
| 重置 | 卸載 → `ntfsfix` 清除髒標誌 → 唯讀重新掛載 | 回報「Resource busy」或用不了的時候 |

### 7.1 讀寫

掛載前會先檢查 macFUSE 與 ntfs-3g 是否就位。缺任何一個都會直接告訴你缺什麼、去哪裡安裝，不會彈出一個看不懂的錯誤，也不會讓你對著不動的圖示猜。

### 7.2 還原為唯讀

這個操作會先卸載目前掛載，再讓系統內建驅動程式重新以唯讀方式掛上。**它不會遺失資料**，前提是此刻沒有程式正在往這塊磁碟裡寫。有正在進行的複製或下載時，先等它結束。

### 7.3 卸載與推出的區別

卸載只是把檔案系統卸下來，裝置仍然連著，可以隨時再掛上。推出是真的把裝置從系統裡斷開，拔線之前做這一下最穩妥。推出之後裝置會從列表中消失，要重新插一次才會回來。

### 7.4 重置

有些故障靠單純重新掛載解決不了，比如上一次異常退出留下的髒標誌、或者某個程式佔著磁碟不放。重置會做三件事：強制卸載、呼叫 `ntfsfix` 清除 NTFS 的髒標誌、以唯讀方式掛回來。清完標誌之後通常就能正常讀寫了。

> [!NOTE]
> `ntfsfix` 清的是「分割區不乾淨」這個標記，它不檢查也不修復檔案內容。如果你的磁碟是在 Windows 非正常關機後出現的問題，清完標誌通常就恢復了；但如果是檔案系統結構本身損壞，需要的是 Windows 內建的磁碟檢查功能，不是這個按鈕。

### 7.5 批次操作

工具列的批次按鈕作用於目前選取的列；沒有選取任何列時作用於全部。批次掛載會依次為每台裝置發起操作 —— 如果沒有儲存管理者密碼，你會看到連續的授權對話框，這是預期行為。

## 8. 掛載參數

掛載時的參數由應用程式統一決定，一個都不需要你手動指定。列在這裡是為了出問題時你能看懂：

| 參數 | 作用 |
| --- | --- |
| `-olocal` | 讓系統把這個卷當作本機卷而不是網路卷。影響它在 Finder 裡出現在「位置」還是「網路」 |
| `-oallow_other` | 允許掛載者以外的處理程序存取這個卷。不開的話只有 root 能讀，桌面環境下等於用不了 |
| `-oremove_hiberfile` | 卷被 Windows 休眠佔用時刪除休眠檔案，換取可寫掛載 |
| `-onoatime` | 不更新檔案的「最後存取時間」。每次讀都寫一次索引記錄是純粹的寫入放大 |
| `-ovolname` | 讓卷在 Finder 裡顯示正確的名稱 |

> [!IMPORTANT]
> `-oremove_hiberfile` 的語意要說清楚：Windows 的「快速啟動」會把關機前的系統狀態寫進休眠檔案，此時 NTFS 卷處於「正在被使用」的狀態。加了這個參數，應用程式會刪掉那個休眠檔案，從而取得寫入權限 —— **代價是 Windows 那邊未儲存的工作階段狀態就此遺失**。如果你在 Windows 裡還有沒儲存的東西，先插回 Windows 正常關機。

## 9. I/O 區塊大小

這是唯一一個面向效能的可調項目，位置在「設定 → 掛載參數」。

macFUSE 向你存取的每個卷暴露一塊「假想儲存裝置」，`iosize` 決定核心向檔案系統發起 I/O 請求時的區塊大小。macFUSE 自身的預設值是 64 KiB，而它官方文件寫得很直白：鏈路快的時候（比如本機磁碟）取大區塊能顯著降低存取開銷。一塊本機 USB 或 Thunderbolt 硬碟顯然屬於「快鏈路」。

| 等級 | 適用情境 |
| --- | --- |
| macFUSE 預設（64 KiB） | 傳統硬碟；以大量小檔案為主、幾乎不做連續大檔案讀寫 |
| 1 MiB（建議） | 預設等級。固態硬碟與外接硬碟的一般情境 |
| 4 MiB | 以超大檔案為主：視訊素材、磁碟映像檔、整顆磁碟備份 |

改完設定對**下一次掛載**生效，已經掛著的裝置需要重新讀寫一次。

> [!NOTE]
> 該參數有格式限制：必須是 2 的次方，最大 32 MiB。應用程式給出的三個等級都在安全範圍內，因此你不需要記這些限制 —— 但如果你在別處手動掛載，請留意。

## 10. 權限與管理者密碼

掛載讀寫需要管理者權限。應用程式提供兩種取得權限的方式。

### 10.1 預設方式：系統授權對話框

每次需要提高權限時彈出 macOS 自己的對話框，密碼由系統驗證，本應用程式全程接觸不到。支援 Touch ID 與 Apple Watch。這是預設方式，安全性更高。

### 10.2 可選方式：儲存管理者密碼

在「設定 → 系統整合」裡開啟「儲存管理者密碼」，輸入一次密碼並點「驗證並儲存」。此後掛載不再彈框。

密碼存在 macOS 鑰匙圈裡，項目類型是通用密碼，歸屬本應用程式的套件識別碼。應用程式自身的任何日誌、任何檔案裡都不會出現這個密碼。

> [!WARN]
> 請如實理解這個取捨：儲存密碼比每次手動輸入**安全性更低**。差別在於密碼由本應用程式代為提交，而不是由系統直接向使用者索取。如果這台 Mac 有他人共用，或者你對機器上軟體的來源沒有把握，請不要開啟它。

### 10.3 開關有三種狀態，不要混淆

| 開關 | 鑰匙圈裡有密碼 | 實際行為 |
| --- | --- | --- |
| 關 | 無所謂 | 每次都彈系統授權對話框 |
| 開 | 沒有 | **仍然彈框**。開關只表達了意圖，此時還沒有可用的密碼 |
| 開 | 有 | 不彈框，用儲存的密碼提高權限 |

第二種狀態會單獨標一列橙色提示，就是為了避免你對著一個開啟的開關納悶「為什麼還是彈框」。

### 10.4 密碼失效時會怎樣

如果你後來改了 Mac 的登入密碼，鑰匙圈裡存的那份就失效了。此時應用程式會：刪掉失效的密碼、在日誌與設定頁說明這件事、並退回系統授權對話框，讓你這一次的操作仍然能完成。不會出現「反覆失敗卻永遠好不了」的情況。

### 10.5 怎麼徹底刪除

把「儲存管理者密碼」開關關掉即可 —— 關閉這個動作本身就包含刪除鑰匙圈裡的項目。也可以在「鑰匙圈存取」應用程式裡搜尋本應用程式的套件識別碼手動刪除。

## 11. 開機行為：四個開關怎麼配合

這四個開關都跟「啟動」和「自動」有關，很容易混淆。它們各自只管一件事：

| 設定項目 | 管的事 |
| --- | --- |
| 系統自動啟動 | 開機時**是否啟動**這個應用程式 |
| 靜默自動啟動 | 開機啟動時**是否開啟主視窗**。開啟後只駐留選單列 |
| 開機自動掛載讀寫 | 啟動那一刻，把**已經插在機器上**的 NTFS 裝置掛載為讀寫 |
| 自動讀寫 | 應用程式執行期間，**之後新插入**的裝置自動掛載為讀寫 |

幾個典型的組合：

- 只想開機就有一塊磁碟可以直接寫：開啟「系統自動啟動」+「開機自動掛載讀寫」。
- 開機即在背景待命、不想看見視窗跳出來：再加上「靜默自動啟動」。
- 不想開機自動掛載，但希望以後插什麼磁碟都自動可寫：只開「自動讀寫」。
- 連授權框都不想要：再開啟「儲存管理者密碼」，此時開機掛載是無人值守完成的。

> [!TIP]
> 「靜默自動啟動」開啟後，應用程式在選單列只留一個圖示，Dock 裡不出現。左鍵點它即可管理裝置；右鍵選單裡有「主介面」；從主介面關掉視窗不會結束應用程式，它會回到選單列繼續待命。

## 12. 選單列圖示與快捷面板

關閉主視窗不會結束應用程式 —— 這是選單列常駐應用程式的基本行為。視窗關掉之後，應用程式從選單列圖示繼續工作。

### 12.1 左鍵點擊圖示

彈出一塊快捷面板，裡面直接列出所有 NTFS 裝置。每台裝置顯示：

- 狀態圖示與卷名；
- 卷的掛載狀態；
- **容量條**：「可用 / 總容量」與佔用百分比；
- 右側的操作按鈕。

不開啟主視窗就能完成掛載、卸載、還原、推出。面板裡顯示的狀態與主介面是同一份資料，不存在兩處不同步的問題。

圖示本身也會變：有裝置處於讀寫狀態時換成另一個圖示，一眼就能看出「現在有磁碟是可寫的」。

### 12.2 操作失敗時面板會說什麼

失敗原因直接顯示在那一列下面，紅色，帶警告圖示，寫的是**完整的一句話**，不截斷。這條設計是必需的而不是錦上添花 —— 快捷面板沒有日誌頁，如果失敗訊息只寫進日誌，你在這個小面板裡點「讀寫」會看到「點了沒反應」：沒有彈框、沒有提示、圖示也不變。

最常見的那一條是相依項目沒裝：此時會明確寫出缺的是 macFUSE 還是 ntfs-3g，以及去「系統相依」頁安裝。

### 12.3 右鍵點擊圖示

選單包含：主介面、重新整理裝置列表、全部讀寫、全部卸載、設定、結束。

## 13. Finder 整合

應用程式內建一個 Finder 擴充功能。它給 `/Volumes` 下的卷加上兩樣東西。

### 13.1 卷標徽章

在 Finder 裡看卷的圖示，右下角會有一個小徽章，寫著目前狀態：**讀寫**、**唯讀**、**未掛載**。不用回到應用程式就能知道這塊磁碟現在能不能寫。

### 13.2 右鍵選單與工具列

Finder 工具列上會出現本應用程式的按鈕，點開是「開啟 NTFSMount」。在 `/Volumes` 下的卷上點右鍵，會多出一組選單項目：

- 掛載為讀寫
- 卸載
- 還原唯讀
- 推出
- 重置卷（ntfsfix）
- 在 NTFSMount 中顯示

在 Finder 裡就能直接完成操作，不必切回主視窗。

> [!NOTE]
> Finder 擴充功能由系統依需求載入，首次使用可能需要一點時間才出現在選單裡。如果一直不出現，去「系統設定 → 一般 → 登入項目與擴充功能 → Finder 擴充功能」確認它處於開啟狀態。

## 14. 操作日誌

「操作日誌」頁記錄每一次操作的時間、內容與結果。它預設關閉，需要到「設定 → 一般」裡開啟「啟用操作日誌」才會開始記錄。

面板裡可以清空日誌，也可以把它匯出成文字檔。日誌只寫在本機的應用程式支援目錄下，不會上傳到任何地方。

遇到問題要回報時，請把匯出的日誌一併附上 —— 裡面的失敗原因通常是判斷問題的關鍵，光看現象描述往往猜不到。

## 15. 依症狀疑難排解

| 你看到的 | 真正的原因 | 怎麼辦 |
| --- | --- | --- |
| 列表裡沒有我的磁碟 | 分割區不是 NTFS；或裝置尚未被系統辨識 | 先確認這塊磁碟確實是 NTFS 格式；拔掉重插一次；點「重新整理」 |
| 提示缺少 macFUSE / ntfs-3g | 相依項目沒裝 | 到「系統相依」頁依指引安裝 |
| 提示 Windows is hibernated | Windows 開了快速啟動，卷被休眠檔案佔用 | 插回 Windows，執行 `shutdown /s /t 0` 完全關機，再插回來 |
| 提示 Resource busy | 有程式正在使用這塊磁碟 | 關掉佔用它的程式；或用「重置」按鈕 |
| 提示權限不足 | macFUSE 的系統擴充功能沒被允許 | 「系統設定 → 隱私權與安全性」裡允許 macFUSE，然後重新啟動 |
| 提示密碼錯誤 | 儲存的密碼已失效 | 重新在設定裡輸入並儲存一次 |
| 掛載後寫不進去 | 實際上還是唯讀掛載 | 看這一列狀態是否為「可讀寫」；不是就再點一次「讀寫」 |
| 傳輸中途掉盤 | 硬體或供電問題 | 換線、換埠；避免使用無獨立供電的 USB Hub |
| Finder 擴充功能不出現 | 擴充功能未啟用 | 「系統設定 → 一般 → 登入項目與擴充功能」裡確認已開啟 |

## 16. 卸載與徹底清理

1. 先把所有 NTFS 裝置「還原為唯讀」或「推出」，不要讓它們停在讀寫狀態。
2. 結束應用程式。選單列圖示右鍵 → 結束，或按 ⌘Q。
3. 到「設定 → 系統整合」裡關閉「系統自動啟動」—— 否則重新啟動後它會再回來。
4. 把應用程式從「應用程式」檔案夾拖到垃圾桶。
5. 如果開啟過「儲存管理者密碼」，到「鑰匙圈存取」裡搜尋本應用程式的套件識別碼並刪除對應項目。
6. 若不再需要掛載 NTFS，可以一併卸載這兩個相依項目。Homebrew 是 `brew uninstall ntfs-3g-mac` 與 `brew uninstall --cask macfuse`，MacPorts 是 `sudo port uninstall ntfs-3g macfuse`。

應用程式的設定檔位於 `~/Library/Application Support/NTFSMount/`，刪掉該目錄即可清除全部設定。
