# NTFSMount ユーザーマニュアル

## 1. このツールができること、できないこと

macOS は標準で NTFS を**読み取り**できますが、書き込みはできません。NTFSMount が補うのはこの書き込みの部分です。成熟したオープンソースの NTFS ドライバである `ntfs-3g` を呼び出し、`macFUSE` が提供するユーザー空間ファイルシステムのフレームワークと組み合わせて、NTFS ボリュームを読み書き可能な状態でマウントし直します。これにより、Finder 上でも通常のディスクと同じようにファイルを保存できるようになります。

同じくらい重要なのは、このツールが**やらない**ことです。以下のことはいずれも行いません：

- フォーマット、パーティション分割、ファイルシステム形式の変換は行いません；
- パーティションテーブルを変更せず、ブートレコードにも触れません；
- Windows のアクセス制御リスト（ACL）と暗号化の仕組みには関与しません；
- データ復旧は行いません。「リセット」機能の `ntfsfix` は「ダーティフラグ」を消すだけで、ファイルの内容を修復するものではありません；
- バックグラウンドにサードパーティのプロセスを常駐させず、ネットワークにも接続せず、いかなる情報も送信しません。

> [!WARN]
> NTFS への書き込みを伴う操作には、どのツールを使う場合でもリスクが伴います。あるディスクに初めて書き込み操作を行う前に、その中の重要なファイルを別途バックアップしてください。本ツールは「現状のまま」提供され、データの損失について責任を負いません。

> [!IMPORTANT]
> データの完全性は、その大部分がハードウェア自体に依存します。品質の低いフラッシュメモリを使った USB メモリは、継続的な書き込み時に速度が低下したり、エラーを出したり、最悪の場合は接続が切れたりしますが、その挙動はまるでソフトウェアの問題のように見えます。大量の読み書きを行う場合は、読み書き性能が保証されたポータブルハードディスクや SSD タイプの USB メモリを使用してください。

## 2. 動作環境と依存関係

| 項目 | 要件 |
| --- | --- |
| オペレーティングシステム | macOS 14.0 以降 |
| プロセッサ | Apple Silicon と Intel の両方に対応するインストーラがあります |
| 必須の依存関係 | macFUSE、ntfs-3g |
| ディスク使用量 | 約 30 MB（アプリ本体は 4 MB 前後） |

依存関係は並列の 2 項目ではなく、1 本のチェーンです：

```
NTFSMount        ->  ntfs-3g        ->  macFUSE        ->  macOS kernel
  (UI)                 (driver)           (framework)        (system)
```

`ntfs-3g` は NTFS のディスク構造を理解していますが、それ自体では macOS カーネルと直接やり取りできません。カーネルからのファイル要求を自分に転送してもらうための「ユーザー空間ファイルシステム」という中間層が必要で、それが `macFUSE` です。どれか 1 つでも欠けると、マウントは成功しません。

> [!NOTE]
> 本アプリは完全なネイティブ実装です。インターフェース、デバイス検出、マウント処理はすべてシステムフレームワークで構成されており、サードパーティのランタイムも、常駐する補助プロセスもありません。デバイスの抜き差しは OS ネイティブの IOKit と DiskArbitration の通知によって検知し、ポーリングは行いません。アイドル時の CPU 使用率はほぼ 0 です。

## 3. システム依存関係の準備

### 3.1 まずアプリに不足しているものを教えてもらう

アプリを開き、「システム依存関係」ページに移動して、右上の「依存関係をチェック」をクリックします。このページには 4 項目の実際の状態が表示されます：

1. macOS のバージョンが最低要件を満たしているか；
2. Xcode Command Line Tools がインストールされているか（ntfs-3g のインストール時に必要になる場合があります）；
3. macFUSE が揃っているか；
4. ntfs-3g が揃っているか。

各項目は展開でき、展開するとその項目で何をインストールすべきか、どのコマンドでインストールするかが表示されます。コマンドの横にはコピーボタンがあります。不足している項目は赤、インストール済みの項目は緑で表示されます。

> [!TIP]
> 依存関係をインストールした後、アプリを再起動する必要も、「依存関係をチェック」をもう一度クリックする必要もありません。このページは 3 秒ごとに自動で再チェックします（純粋なファイルシステムのチェックのみで、プロセスは起動しません）。ターミナルで `brew install` や `port install` が完了したら、ウィンドウに戻るだけで状態が自動的に緑に変わるのを確認できます。

### 3.2 MacPorts（Intel Mac での推奨）

```bash
sudo port install macfuse
```

```bash
sudo port install ntfs-3g
```

MacPorts はすべてを `/opt/local` 以下にインストールします。本アプリは `/opt/local/bin` も検索対象に含めるため、インストール後すぐに認識されます。`PATH` を設定する必要も、アプリに場所を教える必要もありません。

### 3.3 Homebrew（Apple Silicon での推奨）

```bash
brew install --cask macfuse
```

```bash
brew tap gromgit/homebrew-fuse && brew install ntfs-3g-mac
```

`ntfs-3g-mac` という tap は、Apple Silicon に適合したビルド版を提供しています。

### 3.4 リリースページから手動でインストールする

パッケージマネージャを使わず、プロジェクトのリリースページからダウンロードしてインストールすることもできます：

- macFUSE：https://macfuse.github.io
- ntfs-3g：https://github.com/tuxera/ntfs-3g

自分でインストールする場合によくあるのはパスの問題です。標準以外の場所にインストールすると、アプリが見つけられません。そのような場合は、実行ファイルが `/usr/local/bin`、`/opt/local/bin`、`/opt/homebrew/bin` のいずれかにあることを確認してください。

### 3.5 インストール順序と検証

先に `macFUSE`、次に `ntfs-3g` です。逆にすると、後者はフレームワークを見つけられずインストールに失敗します。

インストール後にターミナルで一度検証します：

```bash
ntfs-3g --version
```

バージョン番号が出力されればパスは正常です。アプリが認識するのはこの実行ファイルです。

> [!IMPORTANT]
> macFUSE をインストールすると、macOS がそのシステム機能拡張をブロックし、通知を表示します。「システム設定 → プライバシーとセキュリティ」に移動し、下部にある macFUSE からの項目を見つけて「許可」をクリックし、その後表示される指示に従ってコンピュータを再起動する必要があります。この手順を行わないとマウントは失敗し、権限の問題として報告されます。NTFS 自体とは関係ありません。

### 3.6 バージョンについて

アプリは `ntfs-3g` のバージョンを一度チェックします。推奨バージョンより低い場合は依存関係ページにアップグレードの案内が表示され、既知のリグレッションがあるバージョン（ファイルやディレクトリを新規作成できなくなるもの）には明確な警告が表示されます。アプリが代わりにアップグレードすることはなく、アップグレードが必要であることだけを伝えます。

## 4. 最初のマウントを完了する

1. NTFS 形式のポータブルディスクを接続します。macOS はまずそれを**読み出し専用**でマウントします。Finder ではボリュームが見えますが、書き込みはできません。
2. NTFSMount を開き、「NTFS デバイス」ページに切り替えて、「更新」をクリックするか自動更新を待ちます。
3. 一覧から目的のデバイスを見つけ、「デバイスのマウントポイント」の列に読み出し専用の状態が表示されているか確認します。
4. この行の右側にある「読み書き」ボタンをクリックします。
5. システムの認証ダイアログが表示されるので、Mac のログインパスワードを入力します（「管理者パスワードを保存」を有効にしている場合、この手順は表示されません）。
6. マウントに成功すると、この行の状態が「読み書き可能」に変わり、Finder のボリュームにも正常に書き込めるようになります。

これでボリュームにファイルを書き込めます。使用後にシステム既定の読み出し専用状態に戻したい場合は、この行の「読み出し専用に戻す」をクリックします。このディスクを完全に切断したい場合は「取り出す」をクリックします。

> [!NOTE]
> 手順 5 で表示されるウィンドウは macOS 自体の認証ダイアログであり、本アプリが描画した画面ではありません。Touch ID と Apple Watch に対応しており、パスワードはシステムの `securityd` が直接検証します。本アプリが入力されたパスワードを取得することはできません。これは既定の経路であり、より安全な経路でもあります。

## 5. メイン画面の案内

メインウィンドウは標準的な macOS の分割レイアウトです。左側がナビゲーション、右側がコンテンツ、下部にステータスバーがあります。

### 5.1 サイドバーの 4 つのページ

- **システム依存関係** —— macFUSE と ntfs-3g をチェックし、インストール手順を確認します。
- **NTFS デバイス** —— デバイス一覧とすべての操作はここにあります。
- **操作ログ** —— 毎回のマウント、アンマウント、失敗の時刻と理由。既定ではオフで、設定で有効にする必要があります。
- **ガイドマニュアル** —— 今ご覧になっているページです。左側の目次は検索でき、コードブロックはワンクリックでコピーできます。

設定はサイドバーには**ありません**。macOS の慣例に従い、アプリケーションメニューの「設定…」（⌘,）に配置されています。サイドバーにもう 1 つ置くと、同じ場所を指す 2 つの入口ができてしまうだけです。

### 5.2 下部のステータスバー

ステータスバーは円点と 1 行のテキストで現在の状況を要約します：

| 色 | 意味 |
| --- | --- |
| グレー | 依存関係をチェックしています |
| 緑 | 準備完了。後ろに読み書き可能なデバイス数と読み出し専用のデバイス数が表示されます |
| オレンジ | 問題はありますが致命的ではありません |
| 赤 | 依存関係が不足しており、マウント機能を利用できません |

### 5.3 デバイスページのツールバー

左から右へ：**更新**、**すべて読み書き**、**すべて読み出し専用**、**すべてアンマウント**、**すべて取り出す**。検索ボックスもツールバーにあり、ボリューム名またはデバイス名で絞り込めます。

一括ボタンは**現在選択されている行**に作用します。1 行も選択していない場合はすべてのデバイスに作用します。

## 6. デバイスページ：状態の読み方

### 6.1 3 つの状態

| 表示 | 意味 | 書き込み可否 |
| --- | --- | --- |
| 読み書き可能 | すでに ntfs-3g が引き継ぎ、読み書きモードでマウントされています | 可能 |
| 読み出し専用 | システム内蔵の NTFS ドライバによる読み出し専用マウント | 不可 |
| アンマウント済み | すでにアンマウントしていますが、デバイスは接続されたままです | 不可 |

「アンマウント済み」という状態は意図的に残しています。デバイスを抜く前にアンマウントすることが多く、アンマウント後に一覧から消えてしまうと、デバイスが外れたと勘違いしてしまうためです。完全に消すには「取り出す」を使ってください。

### 6.2 容量バー

各行のデバイス名の下に容量バーがあり、「空き容量 / 合計容量」と使用率を表示します。デバイスがマウントされていないときも容量は表示されます —— 容量はファイルシステムのヘッダー情報を読み取って取得するもので、マウントしなくても得られます。

容量バーの色は 3 段階です：

- 青（既定）—— 使用率が 75% 未満；
- オレンジ —— 使用率が 75% から 90%。注意が必要です；
- 赤 —— 90% を超えています。整理が必要です。

連続的なグラデーションにせず 3 段階にしているのは、このプログレスバーが画面上でわずか数ミリの幅しかなく、そのサイズではグラデーションをまったく判別できないからです。

### 6.3 マウントポイント

「デバイスのマウントポイント」の列には `/Volumes/<name>` のようなパスが表示されます。デバイスがマウントされていないときは「未マウント」と表示されます。読み書きでマウントした後は、このパスが Finder からアクセスできるパスになります。

## 7. デバイスページ：6 つの操作がそれぞれ何をするか

6 つの操作はすべて各行の右側にあります。それらの違いは「マウントする / しない」だけではありません。選び方を間違えると、軽ければ無駄な作業に終わり、重ければ進行中の転送が中断されます。

| 操作 | 実際に行うこと | 使う場面 |
| --- | --- | --- |
| 読み書き | まず現在の読み出し専用マウントをアンマウントし、次に ntfs-3g で読み書きモードでマウントします | ディスクに書き込みたいとき |
| 読み書きをやり直す | まずアンマウントし、読み書きモードで再度マウントします | 読み書き状態で問題が発生し、やり直したいとき |
| 読み出し専用に戻す | アンマウント後、システム内蔵ドライバに戻して読み出し専用でマウントします | 書き込みが終わり、最も保守的な状態に戻したいとき |
| アンマウント | アンマウントしますが、デバイスは一覧に残ります | ディスクを抜く前 |
| 取り出す | システムからこのデバイスを完全に切断します | もう使用しないと決めて、抜き取るとき |
| リセット | アンマウント → `ntfsfix` でダーティフラグを消去 → 読み出し専用で再マウント | 「Resource busy」が報告される、または使えなくなったとき |

### 7.1 読み書き

マウント前に macFUSE と ntfs-3g が揃っているかを確認します。どちらかが欠けている場合は、何が不足しているか、どこでインストールするかを直接伝えます。意味不明なエラーを表示したり、動かないアイコンを見て推測させたりすることはありません。

### 7.2 読み出し専用に戻す

この操作はまず現在のマウントをアンマウントし、次にシステム内蔵ドライバに読み出し専用で再マウントさせます。**データは失われません**。ただし、その時点でこのディスクに書き込んでいるプログラムがないことが前提です。コピーやダウンロードが進行中の場合は、先に終了を待ってください。

### 7.3 アンマウントと取り出すの違い

アンマウントはファイルシステムを切り離すだけで、デバイスは接続されたままなので、いつでも再マウントできます。取り出すとは、デバイスをシステムから本当に切断することであり、ケーブルを抜く前にこれを行うのが最も安全です。取り出した後、デバイスは一覧から消え、再び接続しないと戻ってきません。

### 7.4 リセット

単純な再マウントでは解決できない故障もあります。たとえば、前回の異常終了によって残ったダーティフラグや、何らかのプログラムがディスクを占有し続けている場合です。リセットは 3 つのことを行います。強制アンマウント、`ntfsfix` による NTFS のダーティフラグの消去、読み出し専用での再マウントです。フラグを消去した後は、通常は正常に読み書きできるようになります。

> [!NOTE]
> `ntfsfix` が消すのは「パーティションがクリーンでない」というマークであり、ファイルの内容を検査したり修復したりするものではありません。お使いのディスクが Windows の異常終了後に問題を起こしたものであれば、フラグを消すだけで通常は復旧します。しかし、ファイルシステムの構造自体が破損している場合は、必要となるのは Windows 標準のディスクチェック機能であり、このボタンではありません。

### 7.5 一括操作

ツールバーの一括ボタンは現在選択されている行に作用します。1 行も選択していない場合はすべてに作用します。一括マウントは各デバイスに対して順番に操作を開始します —— 管理者パスワードを保存していない場合、認証ダイアログが連続して表示されますが、これは想定された動作です。

## 8. マウントパラメータ

マウント時のパラメータはアプリが一律に決定するため、手動で指定する必要は 1 つもありません。ここに記載するのは、問題が起きたときに内容を理解できるようにするためです：

| パラメータ | 役割 |
| --- | --- |
| `-olocal` | システムがこのボリュームをネットワークボリュームではなくローカルボリュームとして扱うようにします。Finder で「場所」と「ネットワーク」のどちらに表示されるかに影響します |
| `-oallow_other` | マウントしたユーザー以外のプロセスがこのボリュームにアクセスできるようにします。有効にしないと root しか読み取れず、デスクトップ環境では使えないのと同じです |
| `-oremove_hiberfile` | ボリュームが Windows の休止状態に占有されている場合にハイバネーションファイルを削除し、書き込み可能なマウントを実現します |
| `-onoatime` | ファイルの「最終アクセス日時」を更新しません。読み取りのたびにインデックス記録を書き込むのは純粋な書き込み増幅です |
| `-ovolname` | ボリュームが Finder で正しい名前を表示するようにします |

> [!IMPORTANT]
> `-oremove_hiberfile` の意味を明確にしておきます。Windows の「クイック スタート」はシャットダウン前のシステム状態をハイバネーションファイルに書き込むため、そのとき NTFS ボリュームは「使用中」の状態になります。このパラメータを付けると、アプリはそのハイバネーションファイルを削除して書き込み権限を取得します —— **その代償として、Windows 側の保存されていないセッション状態は失われます**。Windows 側にまだ保存していないものがある場合は、先に Windows に接続し直して正常にシャットダウンしてください。

## 9. I/O ブロックサイズ

これが唯一のパフォーマンス向けの調整項目で、「設定 → マウントパラメータ」にあります。

macFUSE はアクセスする各ボリュームに対して「仮想的なストレージデバイス」を 1 つ公開し、`iosize` はカーネルがファイルシステムに I/O 要求を発行するときのブロックサイズを決定します。macFUSE 自体の既定値は 64 KiB で、公式ドキュメントにもはっきりと書かれています。リンクが高速な場合（たとえばローカルディスク）は大きなブロックを使うことでアクセスオーバーヘッドを大幅に削減できる、と。ローカルの USB や Thunderbolt 接続のハードディスクは明らかに「高速リンク」に該当します。

| 設定値 | 適用場面 |
| --- | --- |
| macFUSE の既定値（64 KiB） | 機械式ハードディスク；大量の小さいファイルが主体で、連続した大きなファイルの読み書きをほとんど行わない場合 |
| 1 MiB（推奨） | 既定の設定値。SSD とポータブルハードディスクの一般的な場面 |
| 4 MiB | 超大容量のファイルが主体の場合：動画素材、ディスクイメージ、ディスク全体のバックアップ |

設定を変更すると**次回のマウント**から有効になります。すでにマウントされているデバイスは、一度読み書きをやり直す必要があります。

> [!NOTE]
> このパラメータには形式上の制約があります。2 の冪である必要があり、最大 32 MiB です。アプリが提供する 3 つの設定値はいずれも安全な範囲内にあるため、これらの制限を覚えておく必要はありません —— ただし、他の場所で手動でマウントする場合は注意してください。

## 10. 権限と管理者パスワード

読み書きのマウントには管理者権限が必要です。アプリは権限を取得する方法を 2 つ提供します。

### 10.1 既定の方法：システム認証ダイアログ

権限昇格が必要になるたびに macOS 自体のダイアログが表示され、パスワードはシステムが検証するため、本アプリは一切関与しません。Touch ID と Apple Watch に対応しています。これが既定の方法であり、より安全性が高い方法です。

### 10.2 任意の方法：管理者パスワードを保存

「設定 → システム統合」で「管理者パスワードを保存」をオンにし、パスワードを一度入力して「検証して保存」をクリックします。以降、マウント時にダイアログが表示されなくなります。

パスワードは macOS のキーチェーンに保存され、項目の種類は一般パスワードで、本アプリのバンドル識別子に属します。アプリ自身のログやファイルにこのパスワードが現れることはありません。

> [!WARN]
> このトレードオフを正しく理解してください。パスワードを保存すると、毎回手動で入力するよりも**安全性が低くなります**。違いは、パスワードがシステムから直接ユーザーに要求されるのではなく、本アプリが代理で送信する点にあります。この Mac を他人と共用している場合、またはマシン上のソフトウェアの出所に確信が持てない場合は、有効にしないでください。

### 10.3 スイッチには 3 つの状態があり、混同しないでください

| スイッチ | キーチェーンにパスワードがある | 実際の動作 |
| --- | --- | --- |
| オフ | どちらでもよい | 毎回システム認証ダイアログが表示されます |
| オン | ない | **それでもダイアログが表示されます**。スイッチは意図を表すだけで、この時点では利用できるパスワードがありません |
| オン | ある | ダイアログは表示されず、保存されたパスワードで権限昇格します |

2 つ目の状態では、オレンジ色の案内が 1 行だけ別途表示されます。これは、オンになっているスイッチを見て「なぜまだダイアログが出るのか」と疑問に思うのを避けるためです。

### 10.4 パスワードが無効になったときの動作

後から Mac のログインパスワードを変更すると、キーチェーンに保存されたものが無効になります。この場合、アプリは無効になったパスワードを削除し、ログと設定ページでその旨を説明し、システム認証ダイアログに戻します。これにより、今回の操作はそのまま完了できます。「繰り返し失敗するが永遠に解決しない」という状況は発生しません。

### 10.5 完全に削除する方法

「管理者パスワードを保存」のスイッチをオフにするだけです —— オフにする操作自体にキーチェーンの項目の削除が含まれています。「キーチェーンアクセス」アプリで本アプリのバンドル識別子を検索して手動で削除することもできます。

## 11. 起動時の動作：4 つのスイッチの組み合わせ

これら 4 つのスイッチはすべて「起動」と「自動」に関係しており、混同しやすいものです。それぞれが担当するのは 1 つのことだけです：

| 設定項目 | 担当すること |
| --- | --- |
| システム起動 | 起動時にこのアプリを**起動するかどうか** |
| サイレント起動 | 起動時に**メインウィンドウを開くかどうか**。開いた後はメニューバーにのみ常駐します |
| 起動時に自動で読み書きマウント | 起動した瞬間に、**すでに接続されている** NTFS デバイスを読み書きでマウントします |
| 自動読み書き | アプリの実行中に、**その後新しく接続された**デバイスを自動的に読み書きでマウントします |

代表的な組み合わせは次のとおりです：

- 起動しただけで書き込み可能なディスクが 1 台あればよい：「システム起動」と「起動時に自動で読み書きマウント」をオンにします。
- 起動時からバックグラウンドで待機し、ウィンドウが飛び出すのを見たくない：「サイレント起動」も追加します。
- 起動時の自動マウントは不要だが、今後どのディスクを挿しても自動で書き込み可能にしたい：「自動読み書き」だけをオンにします。
- 認証ダイアログも不要にしたい：「管理者パスワードを保存」もオンにします。このとき起動時のマウントは無人で完了します。

> [!TIP]
> 「サイレント起動」をオンにすると、アプリはメニューバーにアイコンを 1 つ残すだけで、Dock には表示されません。左クリックするとデバイスを管理できます。右クリックメニューには「メイン画面」があります。メイン画面でウィンドウを閉じてもアプリは終了せず、メニューバーに戻って待機を続けます。

## 12. メニューバーアイコンとクイックパネル

メインウィンドウを閉じてもアプリは終了しません —— これはメニューバー常駐アプリの基本的な動作です。ウィンドウを閉じた後も、アプリはメニューバーアイコンから動作を続けます。

### 12.1 アイコンを左クリックする

クイックパネルが表示され、その中にすべての NTFS デバイスが直接一覧表示されます。各デバイスには次のものが表示されます：

- 状態アイコンとボリューム名；
- ボリュームのマウント状態；
- **容量バー**：「空き容量 / 合計容量」と使用率；
- 右側の操作ボタン。

メインウィンドウを開かなくても、マウント、アンマウント、読み出し専用に戻す、取り出すを完了できます。パネルに表示される状態はメイン画面と同じデータであり、2 か所で同期がずれる問題はありません。

アイコン自体も変化します。読み書き状態のデバイスがあるときは別のアイコンに変わり、「今、書き込み可能なディスクがある」ことが一目で分かります。

### 12.2 操作に失敗したときパネルは何を表示するか

失敗の理由はその行のすぐ下に、赤色で警告アイコン付きで表示され、**完全な 1 文**で書かれ、省略されません。この設計は必須であり、付け足しではありません —— クイックパネルにはログページがなく、失敗情報がログにだけ書き込まれる場合、この小さなパネルで「読み書き」をクリックすると「クリックしても反応しない」ように見えます。ダイアログも出ず、通知も出ず、アイコンも変わらないからです。

最もよくあるのは依存関係がインストールされていないケースです。この場合は、不足しているのが macFUSE なのか ntfs-3g なのかが明確に表示され、「システム依存関係」ページでインストールするよう案内されます。

### 12.3 アイコンを右クリックする

メニューには、メイン画面、デバイス一覧の更新、すべて読み書き、すべてアンマウント、設定、終了が含まれます。

## 13. Finder との統合

アプリには Finder 機能拡張が組み込まれています。これにより `/Volumes` 以下のボリュームに 2 つの機能が追加されます。

### 13.1 ボリュームアイコンのバッジ

Finder でボリュームのアイコンを見ると、右下に小さなバッジがあり、現在の状態が表示されます：**読み書き**、**読み出し専用**、**未マウント**。アプリに戻らなくても、このディスクが今書き込み可能かどうかが分かります。

### 13.2 右クリックメニューとツールバー

Finder のツールバーに本アプリのボタンが表示され、開くと「NTFSMount を開く」となります。`/Volumes` 以下のボリューム上で右クリックすると、メニュー項目のグループが増えます：

- 読み書きでマウント
- アンマウント
- 読み出し専用に戻す
- 取り出す
- ボリュームをリセット（ntfsfix）
- NTFSMount で表示

Finder から直接操作を完了でき、メインウィンドウに戻る必要はありません。

> [!NOTE]
> Finder 機能拡張はシステムが必要に応じて読み込みます。初回使用時は、メニューに表示されるまで少し時間がかかることがあります。いつまでも表示されない場合は、「システム設定 → 一般 → ログイン項目と機能拡張 → Finder 機能拡張」で有効になっていることを確認してください。

## 14. 操作ログ

「操作ログ」ページには、毎回の操作の時刻、内容、結果が記録されます。既定ではオフで、「設定 → 一般」で「操作ログを有効にする」をオンにすると記録が始まります。

パネルではログを消去でき、テキストファイルとして書き出すこともできます。ログは本機の Application Support フォルダにのみ書き込まれ、どこかへアップロードされることはありません。

問題を報告する際は、書き出したログを併せて添付してください —— 中の失敗理由が問題を判断する鍵になることが多く、現象の説明だけでは推測できないことがよくあります。

## 15. 症状別のトラブルシューティング

| 表示される内容 | 実際の原因 | 対処方法 |
| --- | --- | --- |
| 一覧に自分のディスクがない | パーティションが NTFS でない；またはデバイスがまだシステムに認識されていない | まずこのディスクが確かに NTFS 形式であることを確認します；抜いて挿し直します；「更新」をクリックします |
| macFUSE / ntfs-3g が不足していると表示される | 依存関係がインストールされていない | 「システム依存関係」ページで案内に従ってインストールします |
| Windows is hibernated と表示される | Windows のクイック スタートが有効で、ボリュームがハイバネーションファイルに占有されている | Windows に接続し直し、`shutdown /s /t 0` を実行して完全にシャットダウンし、再び接続します |
| Resource busy と表示される | このディスクを使用しているプログラムがある | 占有しているプログラムを終了します；または「リセット」ボタンを使います |
| 権限が不足していますと表示される | macFUSE のシステム機能拡張が承認されていない | 「システム設定 → プライバシーとセキュリティ」で macFUSE を許可し、再起動します |
| パスワードが間違っていますと表示される | 保存されたパスワードが無効になっている | 設定でパスワードを再入力して保存し直します |
| マウント後に書き込めない | 実際にはまだ読み出し専用でマウントされている | この行の状態が「読み書き可能」か確認します；そうでなければ「読み書き」をもう一度クリックします |
| 転送中にディスクが外れる | ハードウェアまたは電力供給の問題 | ケーブルを替え、ポートを替えます；独立した電源を持たない USB ハブの使用を避けます |
| Finder 機能拡張が表示されない | 機能拡張が有効になっていない | 「システム設定 → 一般 → ログイン項目と機能拡張」で有効になっていることを確認します |

## 16. アンインストールと完全なクリーンアップ

1. まずすべての NTFS デバイスを「読み出し専用に戻す」または「取り出す」して、それらを読み書き状態のままにしないでください。
2. アプリを終了します。メニューバーアイコンを右クリック → 終了、または ⌘Q を押します。
3. 「設定 → システム統合」で「システム起動」をオフにします —— そうしないと再起動後に再び起動してしまいます。
4. アプリを「アプリケーション」フォルダからゴミ箱にドラッグします。
5. 「管理者パスワードを保存」を有効にしていた場合は、「キーチェーンアクセス」で本アプリのバンドル識別子を検索し、対応する項目を削除します。
6. NTFS のマウントが不要になった場合は、この 2 つの依存関係も併せてアンインストールできます。Homebrew では `brew uninstall ntfs-3g-mac` と `brew uninstall --cask macfuse`、MacPorts では `sudo port uninstall ntfs-3g macfuse` です。

アプリの設定ファイルは `~/Library/Application Support/NTFSMount/` にあり、このディレクトリを削除すればすべての設定が消去されます。
